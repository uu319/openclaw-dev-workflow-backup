## Mistakes I made here - do not repeat

**1. Correlation is not causation.** `telegram:default` began returning 401 at 10:15:12, 35
seconds after Van stored the QA token. I asserted he had used BotFather `/revoke` on the wrong
bot. He had not; the token he pasted was correct and the QA account started fine on it. The 401
is a separate, older bot. Report the failing account by name and check what actually changed
before proposing a cause.

**2. A SecretRef `id` is not automatically a safe name.** Van pasted a live bot token into
`accounts["qa-engineer"].botToken.id` (he expected me to transfer it to the store). My shape-check
script printed `v.id` unmasked, so a live token landed in the transcript and went to the model
provider. **Never print a SecretRef `id` verbatim** - validate it against
`^[A-Z][A-Z0-9_]{0,127}$` and print only OK / NEEDS ATTENTION. Told him to revoke and re-store;
as of 10:58 he had not (store timestamp still 10:14).

**3. Repairing invalid config.** A bad `id` makes the whole config invalid, and `openclaw config
set` then refuses to write ("Audit, status, health, logs ... still run with invalid config").
Fix was a surgical `node` rewrite of that one field to a proper store ref, mode `0600`, then
`openclaw secrets audit` + `doctor --lint` to confirm. Backup first; my pre-change copy was taken
after his edit and so captured the broken state - snapshot before reading, not after. <!-- project: path:/home/openclaw/.openclaw/workspace -->

## Explaining the store to Van

He asked me to "just transfer" main's token. Store secret values are **write-only** - I can write
them and never read them back. That is why I cannot move a stored token between names or recover
one, and it is worth stating plainly rather than appearing unhelpful.
